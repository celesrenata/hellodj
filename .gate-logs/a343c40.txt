    ami: fix GPU AMI build failure from malformed nvidia-container-toolkit udev rule
    
    The GPU AMI build failed at the udev-rules derivation. Upstream nixpkgs
    services/hardware/nvidia-container-toolkit/default.nix emits a udev rule with
    an unbalanced single quote:
    
      KERNEL=="nvidia", RUN+="... restart nvidia-container-toolkit-cdi-generator.service'"
    
    The trailing `'` is an upstream typo. It was harmless until the NixOS
    udev-rules builder began running `udevadm verify` on the assembled rules,
    which now reports the line as "Invalid key/value pair" and fails the
    udev-rules derivation, cascading to the whole GPU AMI build.
    
    We need hardware.nvidia-container-toolkit enabled for CDI GPU-in-container
    access, so dropping the module is not an option. Instead, build a
    quote-balanced copy of the pinned module directory (single-line sed),
    disable the upstream module, and import the patched copy. This tracks
    upstream automatically: `nix flake update nixpkgs` re-copies and re-applies
    the sed; if upstream fixes the typo the sed matches nothing and the build
    still succeeds.
    
    Verified: the aarch64 udev-rules derivation now builds under emulation with
    udevadm verify reporting Fail: 0.
