# HelloDJ Architecture

## When to use

- Understanding how the HelloDJ bot, web-ui, Lavalink, and streaming sidecars fit together
- Planning changes that touch the single-pod multi-container deployment, YouTube playback, credential store, Activity/video, or voice pipeline
- Checking which container or service owns a given feature/port
- Verifying what must NOT be broken when editing the integration

## When NOT to use

- Actually building/pushing/deploying images or applying manifests (use `hellodj-deployment`)
- Debugging a specific runtime failure (use `hellodj-evidence-debugging` / `hellodj-debug`)
- Designing web UI pages (use `hellodj-modern-web-ui` / `hellodj-webui`)
- Editing the AWS SaaS pipeline or EKS stacks (use `hellodj-session-context`)

## Key facts

### Deployment targets

HelloDJ runs in TWO environments:
1. **On-prem Kubernetes** (gremlin nodes 10.1.1.12–15, namespace `hellodj-service`) — the current live deployment
2. **AWS EKS** (us-east-1, account 874927898283) — the SaaS re-platform (9 CDK stacks). See `platform/infra/ARCHITECTURE.md`.

Source lives in private AWS CodeCommit (not GitHub); local repos have a `codecommit` remote.

### Single-pod, multi-container

The `hellodj` Deployment in namespace `hellodj-service` is ONE pod with:
1. **init: render-lavalink-config** — runs `render_lavalink_config.py` in the bot image; reads ALL credentials from the encrypted SQLite DB and renders a complete `application.yml` to an emptyDir. No sed, no env substitution.
2. **bot** — Python 3.11 Discord bot (wavelink 3.5+), exposes port 8090 for the Activity backend.
3. **lavalink** — custom image with fMP4 HLS + SABR support (port 2333)
4. **tidal-stream** — direct Tidal audio streaming sidecar (port 8801)
5. **spotify-stream** — direct Spotify audio streaming sidecar (port 8802)

Separate deployments: **yt-cipher** (`ghcr.io/kikkia/yt-cipher:master`, 8001), **potoken-server** (`brainicism/bgutil-ytdlp-pot-provider:latest`, 4416), **hellodj-web-ui** (Flask/Gunicorn, 8080).

### YouTube playback pipeline

Playback flows through the custom SABR-capable `youtube-source` plugin. Client order (unified across kube + docker configs):
1. **TV** — OAuth-capable, the ONLY one; primary streaming client with sign-in.
2. **TVHTML5_SIMPLY** — robust unauthenticated playback + search; works on clean IPs without PoToken.
3. **ANDROID_VR** — unauthenticated streaming fallback.
4. **MUSIC** — search only (`playback: false`, `videoLoading: false`)
5. **WEB** — metadata/playlist loading only (`playback: false`)

Auth layers:
- **OAuth (TV)**: refresh token in encrypted credential DB (`youtube.oauth_refresh_token`); pushed to Lavalink `POST /youtube` at startup by `bot.py:push_youtube_oauth()`. `oauth.skipInitialization: true` prevents a broken empty-token poller at boot.
- **PoToken (WEB-family)**: generated by the in-cluster `potoken-server`; `_potoken_refresh_task()` fetches hourly and stores `youtube.pot_token` + `youtube.pot_visitor_data`, then pushes alongside OAuth in ONE `POST /youtube` request.
- **Remote cipher (yt-cipher)**: URL `http://yt-cipher.hellodj-service.svc.cluster.local:8001`, authenticated with `yt-cipher-secret` (`API_TOKEN`), env `OVERRIDE_PLAYER_VARIANT=IAS`.

> The official `youtube-plugin:1.18.2` does NOT support SABR (mid-2026 YouTube serves only SABR to WEB client → "No supported audio streams available"). The custom `youtube-plugin-sabr.jar` baked into the Lavalink image is REQUIRED. There is NO `remotePot` key in the official plugin — don't add one.

### Credential store

All secrets live in an encrypted SQLite DB (`/app/data/hellodj.db`) on the Longhorn PVC. The only env-var secret is `HELLODJ_DB_KEY`. `config.py` `Config` reads from the credential store ONLY — no env fallback.

### Lavalink config rendering

The init container's `render_lavalink_config.py` (runs in the bot image, has Python + cryptography) reads the credential store, renders a complete `application.yml`, writes to `/out/application.yml` (emptyDir), and Lavalink mounts it read-only via subPath. The configmap (`kube/configmap.yaml`) is documentation/reference ONLY — not used at runtime.

### Critical "DO NOT break" list (summary)

1. The init-container Python renderer — update it if credential keys change; data volume is read-only in init.
2. The single `POST /youtube` request — send OAuth AND poToken together; the plugin replaces ALL fields per call.
3. `yt-cipher-secret` API_TOKEN — must match `remoteCipher.password` in rendered config.
4. `HELLODJ_DB_KEY` — changing it invalidates all stored credentials.
5. Player retry logic — `MAX_TRACK_RETRIES=3`, `RETRY_BACKOFF_SECONDS=1.5` (don't remove; YouTube has transient failures).
6. LavasRC provider order — SoundCloud first is intentional (YouTube unreliable mid-2026).
7. Direct-stream sidecars share `/app/data` — mount the SAME `hellodj-data-pvc`.
8. `dnsConfig.nameservers: [192.168.42.1, 192.168.99.42]`, NO custom `search` domains (adding `search celestium.life` breaks plugin downloads).
9. TCP keepalive sysctl `net.ipv4.tcp_keepalive_time: "60"` — prevents gateway websocket stalls.
10. SecurityContext `runAsUser/runAsGroup/fsGroup: 1000`, `supplementalGroups: [26]`, `privileged: true` — changing UIDs breaks volume permissions.
11. PoToken refresh graceful degradation — must NOT crash if potoken-server is down.
12. Activity port 8090 — keep service + ingress `/activity/` in sync.
13. HLS tmpfs volume — RAM-backed (`medium: Memory`, 2Gi); don't switch to disk-backed (latency).
14. UnifiedControlView persistence — `timeout=None`, fixed `custom_id`, registered via `bot.add_view()` in setup_hook.
15. Kustomize image overrides — check BOTH `kube/kustomization.yaml` AND `deployment.yaml` (Lavalink tag is set directly in deployment.yaml, not overridden).

### Config drift warning

THREE sources of Lavalink config exist: `kube/configmap.yaml` (NOT used at runtime), `bot/lavalink/application.yml` (docker-compose local dev), and `bot/render_lavalink_config.py` (**THE ACTIVE PRODUCTION CONFIG**). All three share the same client list: TV, TVHTML5_SIMPLY, ANDROID_VR, MUSIC, WEB — keep them in sync.

## Ingress

- Host: `hellodj.celestium.life`
- `/activity/` → `hellodj:8090` (Activity frontend + WebSocket hub)
- `/` → `hellodj-web-ui:8080` (Web config UI)
- TLS: cert-manager + Let's Encrypt (`celestium-le-production`), ingress class traefik
- WebSocket: Traefik auto-upgrades on `Upgrade: websocket` header (no special annotation needed)

## Bot Dockerfile key details

- Base `python:3.11-slim`; FFmpeg 9 built from source with QSV (libvpl), VA-API, libx264, libx265, libopus, libdav1d, OpenSSL (HTTPS for Tidal HLS)
- Intel VA-API driver + libmfx-gen for hardware transcoding; yt-dlp installed
- Requirements split into layers core → torch → AI (prevents registry push timeouts)
- Stickers directory copied for whiteboard feature; wake word model optionally baked in or volume-mounted
